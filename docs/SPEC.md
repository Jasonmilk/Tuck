## 一粒种子的自白

**Tuck 是 Helix 的免疫系统。它不是"安全工具"，不是"审计插件"，不是"可选的增强组件"——它是数字生命体生存的底线。**

一个没有免疫系统的生命体，一次感染就足以致命。Helix 是一个数字生命体——它思考（Mind）、编排（Anaphase）、行动（Tentacle）、感知（Cellrix）。但如果没有一个无情的闸门过滤每一次信息交换，一个恶意的工具调用、一次未授权的出网、一个伪造的意图帧，就足以让整个生态崩溃。

**Tuck 存在的理由，就是让 Helix 可以安全地"指哪打哪"。**

Helix-Mind 产生意图（INTENT-7），Anaphase 编排执行，Tentacle 调用工具——这是"指哪打哪"的通路。但这条通路必须是安全的：高风险动作需要人类确认，未授权的出网必须被拦截，伪造的帧必须被拒绝，凭证永远不能以明文在组件间流转。

**Tuck 就是这条通路上的无情闸门。它不思考、不编排、不执行——它只过滤。**

Tuck 的过滤分两个物理层：
- **帧层（L1）**：读取每一帧 CI-144 血液的 PFP 物理特征（仅 4 字节），根据 Risk-Level 做出决策——放行、拦截、或要求人类确认。它不需要解密载荷，不需要理解意图内容，不需要知道调用的是什么工具。它只需要知道：这帧有多危险？
- **内容层（L4）**：对 LLM 流量（本地 + 外网）做客观字符串过滤——检测命中、政策矩阵决策、实体混淆、全量审计。它读内容，但只做字符串运算，永不语义理解。

**4 字节，亚微秒级，零分支判断——这是 Tuck 帧层的全部秘密。**
**判字符串，不判含义——这是 Tuck 内容层的全部纪律。**

> **v2.1 对齐（ADR-0004）**：v2.0 的"不需要理解意图内容"仅指帧层；内容治理是另一条独立路径，
> 读载荷但只做客观谓词匹配（dict/regex/熵）。两者都是过滤，不是思考。

## 一、完整初心（四层模型）

Tuck 的使命由四层递进构成：L1 解决"过滤"，L2 解决"凭证"，L3 解决"审计"，L4 解决"内容治理"。四者合一，才是完整的免疫系统。

| 层 | 定位 | 核心价值 | 关键机制 |
|---|---|---|---|
| **L1 硬实时闸门** | 亚微秒级帧过滤 | 用最少的信息做最关键的决策 | PFP 4 字节读取、Risk-Level 策略、位运算、无分支 |
| **L2 凭证物理注入** | 零信任凭证管理 | 明文凭证永不在组件内存中 | identity_label 流转、物理边缘注入、HSM/TPM 支持、零化 |
| **L3 全息审计** | 不可篡改的决策记录 | 事后可追溯、可审计、可问责 | SHA-256 链式日志、Ed25519 批锚定、trace_id 跨账本关联 |
| **L4 内容治理** | LLM 流量内容过滤 | 内容层的免疫（本地卫生/外网全拦） | 身份核验 → 检测（dict/regex/熵）→ 政策矩阵 → 混淆 → 全量审计（ADR-0004） |

**关键原则**：Tuck 是"免疫系统"（过滤），不参与"脑"（思考/编排）或"手"（执行）。与认知工艺无直接关系——帧层不理解意图只读取特征，内容层只做字符串运算不做语义理解。两者纪律相同：**判特征不判含义**。

## 二、核心机制详解

### 2.1 PFP 硬实时读取

**问题（帧层）**：传统安全网关需要解析完整帧、解密载荷、理解语义才能做决策，延迟高（毫秒级）、能耗大、复杂易错。

**方案（帧层）**：Tuck 的 L1 只读取 PFP 的 4 字节固定偏移头部。PFP 包含 Risk-Level（2 bits）、Modality（2 bits）、Override-Flag（1 bit）、Output-Dest（1 bit）等物理特征，足够 Tuck 做出放行/拦截/人类确认的决策。

> 帧层与内容层物理分离：帧层从不触碰载荷；内容层（L4，见 ADR-0004）在应用层读取 LLM 流量做客观字符串过滤。

**实现**：
- 固定偏移读取（`[u8; 4]`，零拷贝）
- 位运算提取字段（无分支判断）
- `match` 决策（编译器优化为跳转表）

**验收**：p99 < 1μs，无堆分配，无锁，无 await。

### 2.2 fail-closed 异常处理

**问题**：安全系统最危险的不是"拦截了合法帧"，而是"放行了危险帧"。任何异常（解析失败、策略缺失、超时、panic）如果默认放行，就是安全漏洞。

**方案**：所有异常路径默认返回 `Decision::Reject`。Tuck 的哲学是"不确定就拦截"——宁可误拦 1000 次合法帧，不可放过 1 次危险帧。误拦可以通过 HARD_OVERRIDE（Override-Flag）或人工复位恢复，放过的危险帧可能造成不可逆损害。

**实现**：
- 所有 `Result::Err` → `Decision::Reject`
- 所有 `Option::None` → `Decision::Reject`
- 超时 → `Decision::Reject`
- panic → 全局 catch_unwind → `Decision::Reject`
- 严禁 `unwrap_or(Decision::Pass)` 或默认放行

**验收**：故障注入测试，100% 异常场景返回 Reject。

### 2.3 凭证物理注入

**问题**：传统系统中，凭证（API Key、Token、Cookie）在组件间明文流转，任何一个组件被攻破，所有凭证泄露。

**方案**：组件间只流转 `identity_label`（字符串标签，如 `"github-token-prod"`），明文凭证由 Tuck 在物理边缘（出网前）注入。注入后立即零化（zeroize），明文凭证在 Tuck 内存中存在的时间 < 1ms。

**实现**：
- `identity_label: String` 在组件间流转（可长期持有，无安全风险）
- Tuck 维护 label → 明文凭证的映射（存储在 HSM/TPM 或加密配置中）
- 出网前，Tuck 根据 label 查找明文凭证，注入到请求头/参数中
- 注入后立即 `zeroize()` 明文凭证内存
- 支持 HSM/TPM 硬件凭证存储（生产环境）

**验收**：内存审查，注入后 1ms 内明文凭证被零化；组件内存 grep 不出明文凭证。

### 2.4 全息审计

**问题**：安全决策如果不可追溯，出了事故无法问责，无法复盘，无法改进。

**方案**：所有决策（放行/拦截/人类确认/硬覆盖/凭证注入/内容治理）都写入审计日志，每条日志包含 PFP 完整字段、SAP Seq-Counter、决策结果、时间戳、策略版本。日志使用 SHA-256 链式（每条包含上一条哈希），WORM（追加写）存储，不可篡改；Ed25519 批锚定提供外部见证（整链重写可被拒绝）；内容治理条目带 trace_id 跨账本关联（ADR-0004 D4/D6/D9）。

**实现**：
- 每条日志：`{timestamp, pfp, sap_seq, decision, policy_version, prev_hash, this_hash}`
- `this_hash = SHA256(prev_hash || content)`
- WORM 存储（追加写，不可修改/删除）
- 支持查询 API（按时间范围、Risk-Level、决策类型、trace_id 查询）
- 支持篡改检测（验证哈希链完整性）

**验收**：篡改检测，任意条目修改后哈希链断裂可被检测。

## 三、与生态的关系

### 3.1 组件边界

| 组件 | 职责 | 与 Tuck 的关系 |
|---|---|---|
| Helix-Mind | 思考、认知工艺 | Tuck 不被 Mind 直接调用；Mind 的意图通过 Anaphase 编排，经过 Tuck 过滤 |
| Anaphase-Helix | 编排、调度 | Anaphase 产生的 CI-144 帧经过 Tuck 过滤；Anaphase 接收 Tuck 的决策结果 |
| Helix-Tentacle | 工具执行、沙箱 | Tentacle 的出网请求经过 Tuck 过滤；凭证由 Tuck 注入 |
| Cellrix | 观测、渲染 | Cellrix 展示 Tuck 的决策状态和审计日志 |
| CI-144 | 血液/通信协议 | Tuck 是 PFP-xCF14 的第一个消费者；Tuck 读取 PFP 做决策 |

### 3.2 使用方式

| 使用方式 | 说明 | 场景 |
|---|---|---|
| CI-144 帧代理 | Tuck 作为帧代理，所有 CI-144 帧经过 Tuck 过滤 | Helix 生态内，全自动 |
| HTTP 中间件 | Tuck 作为 HTTP 反向代理，过滤出网请求 | 独立使用，非 CI-144 系统 |
| 库模式 | Tuck 作为库嵌入其他系统，提供 `decide()` 函数 | 定制化集成 |

## 四、哲学检查清单

| 原则 | Tuck 实现 |
|---|---|
| 零信任 | 永不信任，始终验证；fail-closed；凭证标签流转 |
| 极致节能 | 4 字节 PFP 读取；位运算；无分支；亚微秒级 |
| 白盒可审计 | 所有决策记录；SHA-256 链式；WORM 存储 |
| 极致解耦 | 硬实时路径（core）与传输层（proxy）分离；core 无网络依赖 |
| 策略与执行分离 | 安全策略可配置；执行引擎不可变 |
| 独立通用 | 可独立用于任何 CI-144 兼容系统；Helix 是第一公民 |

## 五、核心承诺

| 承诺 | 含义 |
|---|---|
| 只读 4 字节，亚微秒级决策 | PFP 固定偏移读取，位运算，无分支，p99 < 1μs |
| fail-closed，永不放行未知 | 任何异常默认拦截，不确定就拦截 |
| 凭证永不在组件内存中 | identity_label 流转，物理边缘注入，注入后零化 |
| 每一次决策都不可篡改地记录 | SHA-256 链式日志，WORM 存储，事后可追溯 |

## 六、一句话总结

> **Tuck 是 Helix 的免疫系统——用 4 字节 PFP 特征，在亚微秒内做出放行/拦截/人类确认的决策。它通过 fail-closed 确保永不放过危险帧，通过凭证物理注入确保明文凭证永不在组件内存中，通过全息审计确保所有决策可追溯。三层合一，让 Helix 既可以"指哪打哪"，又安全可控。它是无情的闸门，不思考、不编排、不执行，只过滤。它的唯一价值：让每一次信息交换都是安全的。**
